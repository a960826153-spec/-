## 欄位字典 (Data Dictionary)

| 欄位名稱 | 原始型別 | 清理後型別 | 說明與格式 |
| :--- | :--- | :--- | :--- |
| `claim_id` | object | string | 理賠案件唯一識別碼（無重複） |
| `policy_id` | object | string | 保單編號 |
| `age` | int64 / float64 | float64 | 保戶年齡（合法範圍 18–100 歲，不合理者標為缺值） |
| `gender` | object | string | 性別（標準化為 `M` / `F`） |
| `city` | object | string | 投保人居住縣市（標準化為 6 縣市，未填者為缺值） |
| `product` | object | string | 保險商品種類（4 種商品） |
| `income` | float64 | float64 | 年收入（NT$，依險種中位數填補） |
| `income_missing` | （新增） | int64 | 收入缺值旗標（1: 原本缺失, 0: 原本有值） |
| `premium` | int64 | int64 | 年繳保費（NT$） |
| `claim_date` | object | datetime64[ns] | 理賠申請日（標準格式 `YYYY-MM-DD`，範圍 2026-01-01 至 2026-09-27） |

| `claim_amount` | object | float64 | 理賠金額（轉為浮點數數值） |
| `ocr_confidence` | float64 | float64 | OCR 文件辨識信心度（0–100） |
| `status` | object | string | 理賠進度狀態（已給付 / 審核中 / 駁回） |

## 清理決策紀錄 (Data Cleaning Decisions)
> 紀錄格式依據 Slide 28「決策紀錄四要素」：**欄位 → 做法 → 理由 → 影響筆數**

### 組員 B（型別與一致性）
1. **[列數去重]**
   - **欄位**：`claim_id`
   - **做法**：保留第一次出現之紀錄，去除重複列。
   - **理由**：`claim_id` 為理賠案件之主鍵，實務上同一理賠案件不應重複建檔。
   - **影響筆數**：移除 30 筆重複列，總列數由 1,230 列降至 1,200 列。
2. **[居住縣市統一]**
   - **欄位**：`city`
   - **做法**：將 11 種不同寫法（含台/臺異體字與英文 `Taipei`、`Kaohsiung`）標準化映射為 6 個直轄市；未填寫者保留為缺值。
   - **理由**：消除異體字與中英混用造成的類別分裂，提升分組統計之準確性。
   - **影響筆數**：有效筆數 1,182 筆分為 6 縣市，另保留 18 筆缺值。
3. **[性別標籤統一]**
   - **欄位**：`gender`
   - **做法**：將「男」統一轉換為 `M`，「女」統一轉換為 `F`。
   - **理由**：標準化為單一字元英文代碼，消除多種編碼混用。
   - **影響筆數**：38 筆「男」轉 `M`（共 586 筆），52 筆「女」轉 `F`（共 614 筆）。
4. **[理賠金額數值轉換]**
   - **欄位**：`claim_amount`
   - **做法**：移除幣別前綴「NT$」與千分位逗號「,」，轉為浮點數型別（float）。
   - **理由**：文字格式無法進行彙總運算與數值分析。
   - **影響筆數**：69 筆特殊字串成功轉為數值，有效值共 1,156 筆，保留 44 筆缺值。
5. **[申請日期解析]**
   - **欄位**：`claim_date`
   - **做法**：統一民國年（115/xx/xx 轉 2026-xx-xx）與斜線分隔符，轉換為標準 `YYYY-MM-DD` 之 datetime 型別。
   - **理由**：統一時間序列尺度，利於時間週期分析與趨勢觀察。
   - **影響筆數**：1,200 筆全數解析完成，日期範圍為 2026-01-01 至 2026-09-27。
6. **[年齡不合理值標記]**
   - **欄位**：`age`
   - **做法**：設定合理範圍（18 至 100 歲），將不合理之數值設為缺值（NaN）。
   - **理由**：異常值（-3, 0, 7, 150, 999 歲）明顯為人為鍵入或辨識錯誤，若不剔除將嚴重扭曲年齡統計。
   - **影響筆數**：5 筆極端不合理值標為缺值，剩餘有效年齡 1,195 筆。

### 組員 A（缺值處理）
1. **[收入缺值旗標]**
   - **欄位**：`income_missing`（新增欄位）
   - **做法**：以二元旗標（1: 原本缺失, 0: 原本有值）標記 `income` 缺失狀態。
   - **理由**：分析發現當文件辨識信心 `ocr_confidence < 75` 時，缺值率高達 44.6%（信心 ≥ 75 僅 4.5%），屬於 MAR（隨機缺失，與信心度相關），保留旗標可維護缺失背後的業務訊號。
   - **影響筆數**：共標記 158 筆缺值（值為 1），其餘 1,042 筆為 0。
2. **[收入分群填補]**
   - **欄位**：`income`
   - **做法**：依投保險種（`product`）分組計算中位數，填補該險種下之收入缺值。
   - **理由**：不同保險產品（如微型保險、意外險、重大疾病險、壽險）投保族群之所得水準具系統性差異，分群填補比整體中位數更能保留群體特徵並減少分布扭曲。
   - **影響筆數**：共填補 158 筆缺值，填補後收入平均數由 NT$ 652,474 調整為 NT$ 642,871（約 65.2 萬調整為 64.3 萬），缺值率歸零。
