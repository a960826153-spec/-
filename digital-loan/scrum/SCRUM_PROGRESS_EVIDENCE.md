## 5. Sprint 1、2 燃盡圖資料限制

本組未保留完整的 Sprint 1 與 Sprint 2 起訖日期、原始每日剩餘 Story Points，以及每日驗收完成紀錄。

部分 GitHub Issues 為期中整理時補建，因此不能直接使用補建日期還原過去 Sprint 的每日工作進度。

截至本次整理，尚無足夠資料製作可驗證的 Sprint 1 與 Sprint 2 正式 Burndown Chart。

為維持專題紀錄的真實性，本組不使用虛構日期或估計的每日剩餘點數冒充原始燃盡資料。

## 7. 後續改善措施

為避免期末發生相同問題，後續 Sprint 將：

1. 在 Sprint 開始前記錄起訖日期。
2. 由團隊確認 Sprint Backlog 與 Story Points。
3. 指派每則工作項目的負責人。
4. 使用 GitHub Projects 更新工作狀態。
5. 保留每日剩餘工作量的紀錄。
6. 每次 Sprint 結束後輸出 Burndown Chart。
7. 保存 Sprint Review 及 Retrospective 紀錄。
8. 透過 Pull Request 與 Review 留存實際協作證據。
